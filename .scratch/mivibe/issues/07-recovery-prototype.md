# 连续录音与待处理内容如何恢复和取消

## Question

用可交互的轻量原型和用户确认以下场景：第一句转写时开始第二句；第一句失败或失焦后恢复/丢弃；两句并存时返回键取消哪一句；“输入到这里”如何保留用户选中的目标；待处理录音和文字何时删除、退出时怎样处理；队列满时如何提示。落实底部不抢焦点浮条与四种已确定状态，不实现正式蓝牙/API/文本注入。

## Context

[已确认的异常行为](04-interaction-contract.md) 是本票的固定前提。原型模拟不得被当作 macOS 不抢焦点或真实输入的技术验收。

## Answer

用户逐一确认原型内嵌设计（原型：[prototypes/recovery-flow-prototype.html](../prototypes/recovery-flow-prototype.html)）：

1. **队列容量 2 条**：第三条录音直接拒绝开始并提示先处理前两句。
2. **顺序约束**：后句可录，但必须等前句成功或被显式处理后才输入；文字出现顺序 = 说话顺序。
3. **返回键语义**：只取消最新活动录音/转写，绝不隐式删除较早待处理内容。
4. **退出时待处理内容**：显式二选一——本地加密保留到下次启动（一次性续命，恢复处理完即删，不形成长期历史）或立即丢弃；无静默保留/删除。此项是 04 票"不保存长期历史"的精确化补充。
5. **浮条与状态**：底部不抢焦点浮条确认"正在听 / 正在转写 / 已输入 / 需处理"四状态，文案带下一步指引；最终视觉不在本票范围。
